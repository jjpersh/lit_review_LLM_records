## 2. Eligibility
Borderline core. A generative LLM (GPT-5.1) writes fault diagnoses and causal explanations for process faults. These are advice to operators. A symbolic verifier checks each explanation before it reaches an operator or supervisory logic (p.21, p.25–27). There is a tested setup: hallucination detection on the authors' 500-scenario Process-Control Hallucination Dataset (p.20–22). No control action is generated, sent or tested. The LLM advises at the operator-interface and diagnosis level only. The CSTR "control plan" examples (p.3–4, p.12) are worked illustrations, not experiments. The domain is process systems (heat exchangers, pumps, CSTRs, cooling loops), simulated or synthetic. I recommend `core` at the lowest authority (Advise), mainly for section 5.2 (safeguards). The weak link to control should be flagged.

## 3. What was built, in plain words
The "plant" is a set of 500 text scenarios about faults such as pump restriction, valve stiction, heat-exchanger fouling, compressor surge, sensor drift and reactor runaway (p.20). The signals come from simplified simulations, "using simulation environments including Modelica…, Aspen HYSYS…, or MATLAB Simulink" (p.21), plus real data "where available". Each scenario contains process signals and maintenance notes, the true fault, a correct explanation, a plausible but wrong ("hallucinated") explanation, an "easy-but-wrong" explanation, and counter-evidence (p.20). No controller is modelled and nothing is actuated.

The LLM (GPT-5.1, called via API) generates a diagnosis and its reasoning. It is "used exclusively for generation, not verification" (p.27). The verifier is a symbolic pipeline in SWI-Prolog and ProbLog. It works in five steps (p.10–11):
1. Split the explanation into discourse units (with an RST parser, or GPT for small high-fidelity runs).
2. Map each unit to logic facts.
3. Weight the facts: higher for main claims ("nucleus") than for supporting context ("satellite").
4. Run abductive search for the cheapest consistent explanation.
5. Rank the candidate explanations.

Counter-abduction then builds rival explanations. A claim is flagged as hallucinated if its defeat score is above 0.5 (p.18–19). The output is accept, reject, or revise, with a justification. It is meant to sit above PID or MPC at the supervisory level, triggered by events rather than run continuously (p.25–26). The configuration (abducibles, constraints, weights) is on GitHub (p.27, p.32).

## 4. Each tested setup
- **Setup 1: D-ALP verifier checking LLM fault explanations on the Process-Control Hallucination Dataset** (p.20–22). Five verifier variants are compared:
  - Baseline ALP (uniform rule weights);
  - ProbALP (probabilistic ALP, no discourse cues);
  - D-ALP-Depth (nucleus/satellite weighting only);
  - D-ALP-Rel (relation-type weighting only);
  - Full D-ALP (both).

  The metric is hallucination-detection F1. Results are "averaged across ten runs and three datasets" (p.21). No variance is given. All comparators are ablations of the authors' own symbolic verifier. Abductive RAG (an external method) was run only on HotPotQA (p.22). No comparison is made with a non-LLM fault-diagnosis method, and the LLM's own diagnostic accuracy is not reported.
- **Not graded (no process data):** the counter-abduction arm (D-ALP + counter-abduction, Tables 17–18, p.24–25), the timing results (Table 10), the consistency results (Table 11), and the human studies (36 participants, Tables 13–15; follow-up with 20 participants). These were run only on general QA and medical datasets (TruthfulHalluc, MedHalluc, eSNLI_Halluc), or no dataset is stated. None reports results on the process-control set.

## 5. Results
- **Process-control detection F1** (Table 9, p.22, read from the page image). F1 is higher-is-better. Results by variant: Baseline ALP 0.57, ProbALP 0.55, D-ALP-Depth 0.60, D-ALP-Rel 0.62, Full D-ALP 0.72. This is the lowest Full D-ALP score of the five datasets (others 0.77–0.83). The denominator is the 500 scenarios; positives and negatives are not described for this set.
- **Overall gain** (p.22): "Full D-ALP achieved 12–18 percentage points improvement over the baseline across datasets". On the process set the gain is 15 points.
- **Defeated hypotheses** (Table 11, p.22, image): Baseline 19% to Full D-ALP 7%, lower is better. The dataset is not stated.
- **Counter-abduction** (Table 17, p.25): "D-ALP + Counter-Abduction … Average … 0.86" against 0.80 without it, on non-process datasets only. Table 18 reports false-positive rate 0.14 to 0.09 (p.25).
- **Verifier reasoning time:** "0.79 s/inference" (Table 16, p.24). This is the symbolic layer, not the LLM.
- **LLM against non-LLM:** the paper does not show the LLM beating a non-LLM alternative. All comparisons are between versions of the symbolic verifier.
- **Detail gaps:** the text never states how many GPT-5.1 explanations were hallucinated, or whether the detector scored LLM outputs or the dataset's pre-written hallucinated explanations.

## 7. Terms to define
- Abduction: inference to the most plausible explanation of an observation.
- Abductive Logic Programming (ALP): a logic program that may assume ("abduce") facts to explain observations, subject to integrity constraints.
- Counter-abduction: generating rival explanations of the same evidence. The original explanation is defeated if a rival scores higher.
- D-ALP (Discourse-weighted ALP): ALP where assumed facts are weighted by their role in the text: main claim (nucleus) or supporting context (satellite).
- RST (Rhetorical Structure Theory): a parse of text into units linked by relations such as Cause, Evidence and Contrast.
- Defeat score: the share of validators that find a better-scoring rival. Above 0.5 means hallucinated.
- Easy-but-wrong explanation: a plausible explanation that contradicts trends or counter-evidence in the scenario.
