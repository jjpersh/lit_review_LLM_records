- Title as printed: "Autonomous Industrial Control using an Agentic Framework with Large Language Models".
- Venue: arXiv preprint, cs.MA. It uses a 2-column IFAC-style layout, but no conference is named in the text.
- Peer review: preprint (no peer-reviewed venue stated).

## 2. Eligibility
Yes. A set of LLM agents built in CrewAI (operator, validator and reprompter, all running OpenAI GPT models) decides the heater on/off state of a physical TCLab board. The command goes to the hardware through a Python wrapper (pp.4–5). It is a closed loop on lab hardware, and the plant is a standard thermal teaching rig in process control. It is a core paper.

## 3. What was built, in plain words
The plant is a physical TCLab (Temperature Control Lab): an Arduino board with transistor heaters and temperature sensors (p.4). The task is a thermostat with hysteresis, i.e. relay control. The heater must be switched off above 27 °C and on below 25 °C, which makes the temperature cycle inside that band. Each run lasts 40 minutes (p.4).

No conventional controller is used. The LLM "Operator Agent" is itself the controller. Its inputs are the current state (heating or cooling), the current temperature and the two thresholds. It must output one integer, 1 for heating or 0 for no heating (Fig. 4, p.5). **Actuation is threshold-based on/off switching, not continuous heater power.** The heater-power traces in Figs 5–8 (p.5) switch between 0 and about 0.3 W.

A "Validator Agent" checks each proposed action against the threshold logic. The general framework uses a digital twin (a simulation model of the plant) for this check. Here, however, the authors say the task is simple enough that they "embed it into the Validator Agent" (pp.4–5). If validation fails, a "Reprompter Agent" refines the action, and the result is validated again before it is applied (p.4). The paper does not say how many reprompts are allowed in the case study. It also does not say what is sent to the plant when a reprompt fails, although such failures are plotted in Figs 5–8. The models are GPT-3.5, GPT-4o-mini, GPT-4o and GPT-4, called through the OpenAI API (p.5). The agents are prompted through role, goal and backstory fields (Fig. 3) and are not fine-tuned. Sampling settings (temperature and similar) are not reported. The control sampling rate is not fixed: it is set by the model's inference time (p.5).

## 4. Each tested setup
**Setup A: LLM operator, validator and reprompter doing on/off thermostat control of a physical TCLab (E3).**
- Conditions: band of 25–27 °C, 40 min per run, starting from ambient (Figs 5–8). No disturbance or fault was injected.
- Runs: one run per model, four models in total.
- Number of decisions per run (Table 1, p.5): 423 for GPT-3.5, 394 for GPT-4o-mini, 554 for GPT-4o, 128 for GPT-4.
- Comparator: none. No relay or PID baseline was run, and there was no non-LLM run of the same thermostat rule.
- Metrics:
  - first-pass accuracy, and accuracy after reprompts, of the operator's decisions (Table 1);
  - average deviation from the band midpoint, time above 27 °C, time below 25 °C and total time outside the band (Table 2, p.6).
- What was varied: the LLM only. The architecture was fixed. No ablation without the validator was run, but first-pass accuracy works as an ablation of the reprompting step.

## 5. Results
- **Decision accuracy (Table 1, p.5).** "Accuracy- first pass (%) 60.04 ... 72.49 ... 99.63 ... 93.75", for GPT-3.5, GPT-4o-mini, GPT-4o and GPT-4. The share is of operator decisions accepted by the validator on the first try; the denominators are 423, 394, 554 and 128 samples. Higher is better.
- **Accuracy after reprompting (Table 1).** "Accuracy - reprompts (%) 85.34 89.97 99.81 96.09".
  - In counts: GPT-3.5 had 169 first-pass failures, of which 107 passed after reprompting. GPT-4o had 2 failures, of which 1 passed.
  - The text gives "60.4%" on p.6, a typo for 60.04%.
- **Sampling rate (p.5).** "the sampling rates for GPT 4o is the highest while GPT 4 has the lowest sampling rate". The authors attribute this to inference time. No latency is reported in seconds.
- **Control performance (Table 2, p.6).** "Average Deviation 0.832 0.077 0.582 1.469" (GPT-3.5, GPT-4o-mini, GPT-4o, GPT-4).
  - This is the mean temperature deviation from the 26 °C band midpoint, in °C (units implied). Lower is better.
  - Time outside the band, over a run of about 2400 s: 949.24 s (GPT-3.5), 931.40 s (GPT-4o-mini), 1173.58 s (GPT-4o) and 1336.50 s (GPT-4). Lower is better.
  - This means the temperature was outside the 25–27 °C band for roughly 40–55% of each run, for every model.
- **Why GPT-4 did worst (p.6).** "For GPT 4 the inference time was high resulting in previous action being implemented for an extended period of time". With no cooling, residual heat drives overshoot.
- **Comparison with non-LLM control.** The paper does **not** show the LLM beating a non-LLM alternative. No non-LLM baseline was run, even though the task is a two-threshold relay rule that a conventional on/off controller performs trivially.

## 6. Duplicates
S037 (Vyas and Mercangöz, 2025, arXiv:2507.07115) is by the same authors. It uses the same CrewAI validator–reprompter framework on TCLab hardware, and on p.5 it says it "builds directly on" this paper. **No experiment appears in both papers.**

- **Unique to S038:** the single-loop hysteresis thermostat on one TCLab board, with these details:
  - band of 25–27 °C, 40-min runs;
  - **threshold-based on/off heater switching**, with the operator outputting 1 or 0 (Fig. 4, p.5);
  - no disturbance and no PID comparator;
  - four OpenAI models (GPT-3.5, GPT-4o-mini, GPT-4o, GPT-4);
  - accuracy and band-time metrics (Tables 1–2, pp.5–6).
- **Unique to S037:**
  - **Case study 1:** fault-recovery path planning over finite state machines (no plant).
  - **Case study 2:** two TCLab boards with a fan cooling one heater. There, the action agent sets **continuous heater power (0–0.3 W) for both heaters**, the result is compared with PID on hardware and on a digital twin, and local LLaMA models are also tested (S037 pp.11–15).
- **Shared:** the authors, the framework idea (operator/actor, validator, reprompter), the CrewAI orchestration, the OpenAI models, and the TCLab rig type.

## 7. Terms to define
- **TCLab (Temperature Control Lab):** an Arduino-based teaching kit with heaters and temperature sensors, used here as the physical plant.
- **Operator Agent:** the LLM agent that outputs the heater state (1 = heat, 0 = no heat) from the current temperature and thresholds.
- **Validator Agent:** the LLM agent that checks the operator's action against the threshold logic. In this paper it stands in for a digital twin.
- **Reprompter Agent:** the LLM agent that, after a validation failure, writes a corrective prompt so the operator can revise its action.
- **Reprompting:** sending a model a revised prompt that contains feedback on its rejected answer.
- **First-pass accuracy:** the share of operator decisions accepted by the validator without any reprompt.
- **Digital twin:** a simulation model of the plant used to test actions before applying them. It is proposed but not used in this case study.
- **CrewAI:** an open-source Python framework for orchestrating several LLM agents.
- **Sampling rate (as used here):** how often a new control decision is made, set by LLM inference time rather than by a fixed clock.
