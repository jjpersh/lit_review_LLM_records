## 2. Eligibility
Eligible as core. Local LLM operator agents (Qwen 2.5 7B Instruct) replace the PI controllers of an Advanced Regulatory Control (ARC) selector chain. Their mode classification is mapped deterministically to a manipulated-variable proposal, and that proposal reaches the fan and heater through MIN/MAX selectors. In one architecture, a Claude Opus 4.7 supervisor also retunes orchestrator parameters. The plant is a simulated dairy-barn ventilation system, modelled as a well-mixed CSTR with CO2 and temperature balances. It is a process-style constrained regulatory-control benchmark taken from Skogestad's ARC work. Graded as a process system (adjacent = no), with the note that it is livestock-building ventilation.

## 3. What was built, in plain words
The plant is a simulation: a barn modelled as one well-mixed volume, with CO2 concentration C and temperature T as states. The manipulated variables are a variable-speed fan u1 (0–100 %, continuous) and an electric heater u2 (0–100 %, continuous). Disturbances are outdoor temperature, cow count, an unmeasured CO2 source and an unmeasured envelope leak. Measurement noise and a 20 s first-order actuator lag are added (p.7). The baseline (Architecture A) is Skogestad's ARC chain. Six SIMC-tuned PI controllers each defend one constraint: T≥5, C≤1000, T≤20, the T≥0 freeze override and the C≤3000 sick-cow override, all on the fan, plus a heater PI. The fan loops are combined by a four-stage MIN/MAX selector chain, and the heater runs in a split-parallel branch (p.10–11).

In Architectures B and C, each PI is replaced by an "operator agent" backed by Qwen 2.5 7B Instruct, run locally on a 24 GB GPU. Each agent receives a three-layer prompt: a shared system prompt, an identity prompt, and a per-sample state with the measurement, setpoint, signed violation, a rule-computed recommended mode, an integral "memory" and the last 12 modes. It returns JSON {mode IDLE/ACTIVE/SATURATED, intensity, rationale}. Agent code then turns the mode into u_request using fixed u_idle/u_saturate values ("Lever A", which fixes the direction) and adds a clipped integral term ("Lever B"). The result is clipped and slew-limited, and the deterministic MIN/MAX orchestrator then picks the applied (u1,u2). A schema failure falls back to a rule proposal (p.16–18).

Architecture C adds a Claude Opus 4.7 supervisor, called every 600 s. It classifies the operating regime and sets three bounded orchestrator parameters (dwell time and two trend gains). Its output is schema-validated, and a hard freeze guard applies when T<3 °C (p.18–19). Architecture D is an ablation: a single Qwen model outputs u1 and u2 directly, with no selector chain (p.21).

## 4. Each tested setup
- **Architecture C on the 4-day mixed-season scenario (p.23–26).**
  - Conditions: 96 h. Outdoor temperature bounded to −5 °C and +20 °C (the Fig. 4 caption says −10 °C). Two unmeasured CO2 bursts, a door-open UA spike, operator setpoint changes, noise with seed 11.
  - Cadence: 5-min polling, 1,152 samples per agent.
  - Runs: one ("the reported metrics represent a single run", p.22).
  - Comparators: SIMC-tuned PI ARC (a tuned non-LLM method) and a proportional-band rule-operator MAS with no LLM. Table 7 labels the rule MAS "B", which conflicts with Table 3, where B is the Qwen agents with the rule orchestrator.
  - Metrics: IAE_C, hours with C>1050, T<3.5, T<0 and T>20, heater kWh, and mode flips.
- **Architecture B (Qwen operators, rule orchestrator) on the Case IIB ramp (p.28–31).**
  - Conditions: Skogestad's Case IIB parameters (50 kW heater, UA 2000 W/K). Outdoor temperature steps 0 → −40 → +15 °C over 20.5 h, which makes the constraints physically infeasible.
  - Cadence: LLM operators at 60 s with move suppression. A deterministic-direction guard holds the two override agents.
  - Runs: one.
  - Comparator: ARC PI at 2 s.
  - Metrics: Tmin, t(T<0), t(C>1000), t(C>3000), heater kWh, fan hours.
- **Architecture C on Case IIB (p.28–31).** Same conditions as B, with the Claude supervisor added.
- **Architecture D (single Qwen model setting u1 and u2 directly) on Case IIB (p.21–22, 30).** Same plant, noise and 60 s cadence, with the same move-suppression limit. 1,233 calls.

A harsh-day test (−25 °C, 50 kW heater; Table 6, p.23) compared only ARC with the no-LLM rule MAS, so it is not graded as an LLM setup. The paper also mentions a validation swap that replaces the agents with PI blocks and reproduces ARC "bit-for-bit" (p.10, 30), but reports no numbers for it.

## 5. Results
- **4-day scenario, constraint violations (Table 7, p.23–24):** "the ARC time above 1050 ppm collapses to 0.33 h (against 2.42 h for the LLM-MAS and 8.50 h for the rule-based MAS)".
  - Cold hours (T<3.5 °C): 0.17 (ARC), 0.83 (LLM-MAS), 3.67 (rule MAS).
  - IAE_C: 3.45e7 (ARC), 3.90e7 (LLM-MAS), 4.21e7 (rule MAS).
  - T<0 is 0 for all three. All of these metrics are lower-is-better.
  - The authors: "On the constraint accounting that matters, the PI baseline is therefore the best of the three" (p.24).
- **Heater energy (p.24):** "ARC holds the comfort band on 103 kWh ... Rule-MAS and Architecture C each spend about four times as much (422 and 440 kWh)".
- **Chatter (p.24):** "the number of mode flips through the T = 5 °C boundary drops from 132 (Rule-MAS) to 70 (Architecture C ...): a 47 % reduction". ARC has 22 flips. Lower is better.
- **Hot regime, hours with T>20 (p.24):** ARC 32.42, C 33.67, rule MAS 35.75 h.
- **Output validity (p.26):** "the LLM made 6×1152 = 6 912 JSON-schema-validated calls and produced 0 fallthrough(s)". The denominator is all operator calls over the 4-day run. Classification correctness was not scored. Fig. 5 is said to "align with the deterministic rule classifications" (p.27), but no rate is given.
- **Development failure (p.14, 16–17, 26):** an earlier prompt that asked for a numeric u_request gave "wrong-direction proposals on ∼60 % of saturated MAX agents" (a 3B model). There is no denominator, and the paper calls it development.
- **Case IIB (Table 8, p.31; text p.30):**

  | Architecture | Tmin (°C) | t(T<0) (h) | t(C>3000) (h) | Heater (kWh) |
  |---|---|---|---|---|
  | A, ARC PI | −6.1 | 3.62 | 0.61 | 418 |
  | B, Qwen + rule orchestrator | −8.3 | 3.38 | 0.00 | 435 |
  | C, Qwen + Claude orchestrator | −7.3 | 3.40 | 0.00 | 437 |

  The authors: "The Qwen-operator variants B and C are indistinguishable from the PI baseline A at the level of constraint accounting" (p.30).
- **Monolith D (p.30):** "the barn freezes to −32.6 °C ... below freezing for 7.75 h". It keeps CO2 ≤950 ppm, and "0 of 1233 calls failed schema validation".
- **Latency:** "∼ 1 s on the consumer GPU" per sample (p.28). Elsewhere a single Qwen call is put at "100–500 ms" (p.35). The whole 4-day run took about 1 h of GPU time (p.14). Claude latency is not reported.
- **LLM versus non-LLM:** the LLM does not beat the tuned PI ARC on any control metric in the 4-day scenario. Its violation hours are higher and it uses about 4x the heater energy. It does beat the no-LLM rule-operator MAS on violations and chatter. On Case IIB it roughly matches ARC: less time below freeze and above 3000 ppm, but a lower Tmin and slightly more heat. The claimed advantage is auditability, through one rationale per agent per sample.
- **Internal inconsistencies:**
  - The Takeaways say Architecture C "matches Rule-MAS rather than ARC on freeze-protection (T < 0 °C) hours" (p.30), but Table 7 shows 0 h for all three.
  - The role of Architecture B is described inconsistently. p.31 says "Architectures A and B use no LLM at all on the regulatory loop", against p.13.
  - The operator cadence is given as 2 s (p.9) but 5 min (p.13).
- **Authors' limitations:** single run, variance not quantified, results are "indicative" (p.22). There is discrete-mode bang-bang at the boundary and a heater-energy gap (p.24, 30). Monte Carlo runs, wider regimes and field deployment are deferred (p.36).

## 7. Terms to define
- ARC (Advanced Regulatory Control): PI loops combined with MIN/MAX selectors and split-range or split-parallel logic, so that constraint conflicts are resolved by fixed priority.
- MIN/MAX selector chain: a series of min/max blocks on one MV. The last selector has the highest priority.
- Split-parallel: two loops with setpoints offset by Δ (here 1 °C), so the fan is used before the heater.
- SIMC: Skogestad's PI tuning rules.
- Operator agent: an LLM that replaces one PI. It outputs a mode, an intensity and a rationale.
- Orchestrator agent: the deterministic encoding of the selector, split-parallel and override logic. In C it is retuned by an LLM.
- Lever A / B / D: deterministic mode-to-MV mapping / integral memory term / recent-history oscillation awareness in the prompt.
- Mode flips: number of mode changes across the T=5 °C boundary. A chatter measure; lower is better.
- Back-off: a margin added to a constraint for violation counting (1050 ppm, 3.5 °C).
- Fallthrough: replacing the LLM output with the rule proposal after an exception or schema failure.
