## 2. Eligibility
Core. An LLM agent system (five agents with retrieval-augmented generation) selects a controller architecture (PID, MPC or LQR), tunes its parameters in simulation, and then proposes parameter changes to adapt the deployed controller to the "real" plant; each proposal must pass a simulation safety filter before deployment (pp.3–6). It is tested on a simulated six-span roll-to-roll (R2R) web-handling line under two scenarios (pp.6–9). Process system (continuous web handling, as in printing and coating; p.6). Note: the abstract says "Validation with a lab-scale R2R system" (p.1), but Section 4 states "a simulation study of a R2R web handling system" and the "real system" is itself a simulation, "real system(simulation) Sreal" (p.7). Hardware validation is listed as future work (p.9). Evidence is therefore simulation only.

## 3. What was built, in plain words
The plant is a simulated multi-span R2R line: motorised rollers move a web; the states are web tension in each span and roller velocity; the inputs are continuous motor torques (p.7). Two parameter sets stand in for "reality" and "simulation": Sreal (the plant being controlled) and Ssim, an intentionally mismatched model with 8.3–50% parameter deviations, used for design and safety checks (p.7, Table 1).

The controller that moves the actuators is a conventional controller, finally an LQR (linear-quadratic regulator, state feedback from a Riccati solution) (p.8). The LLM never writes torques. It sits above the controller as a tuner. Five agents with role prompts (Appendix A, pp.10–11) share a RAG knowledge base (control theory, R2R practice, system documents; p.3): SysID Agent (fits plant parameters), Initial Control Agent (tunes PID, MPC and LQR on Ssim over up to 50 iterations and picks the best by a weighted score; Algorithm 1, p.5), Adaptation Agent (reads the performance gap on Sreal, diagnoses a cause, proposes a parameter change Δϕ; Algorithm 2, p.6), Monitoring Agent (detects degradation and diagnoses causes; p.6), and Code Agent (runs simulations and code).

Every proposed change passes a safety filter before deployment: in Ssim it must satisfy input and rate limits, improve the performance vector (RMSE, overshoot, settling time), and keep worst-case deviation under parameter perturbation below a tolerance; all three must hold (Eqs. 16–19, p.5). Rejected proposals go back to the LLM. Humans "retain oversight" (p.3) but no human approval step is described in the tests. The LLM model is not named; Figures 2–3 show an OpenAI logo only (p.4). No fine-tuning is reported.

## 4. Each tested setup
One architecture (LLM proposes and tunes, simulation safety filter gates, LQR acts), tested on one simulated plant in two scenarios:
- **Phase 1 controller selection (in Ssim):** LLM-tuned PID, MPC and LQR compared on RMSE, settling time, overshoot, control effort and computation time; LQR chosen (Table 2, p.8).
- **Scenario A, tension control:** setpoints of 24–40 N in five spans; span 3 steps from 20 N to 44 N at t = 1 s as a disturbance; unwinding speed 0.01 m/s (p.8). Initial deployment plus two adaptation cycles (Adapt1, Adapt2).
- **Scenario B, velocity setpoint change:** all six spans at 30 N; unwinding speed steps 10-fold, from 0.01 to 0.10 m/s, at t = 1 s (p.8). Initial plus three adaptation cycles.
- **Comparator:** an "MPC baseline" under identical conditions (pp.8–9). How it was tuned is not reported; it is presumably the Phase 1 MPC tuned on the mismatched Ssim and not adapted on Sreal, so the comparison is between an adapted LQR and an unadapted MPC (inference flagged; the paper does not say).
- **Off-nominal:** 8.3–50% model mismatch, step disturbance, large speed transient, stochastic disturbance term in the model (p.7).
- **Runs:** one trajectory per configuration; no repeats or variance. Number of LLM proposals made, rejected by the safety filter, or iterations used is NR. Monitoring Agent (Phase 3) and model refinement (Phase 4) are described but not tested.

## 5. Results
- Phase 1, Table 2 (p.8), in Ssim: LQR eRMSE 0.3811 N versus PID 0.4813 N and MPC 0.5843 N; LQR settling 1.62 s (slowest), overshoot 16.31%. Lower is better. All three controllers were tuned by the LLM.
- System identification: identified model has "1.4-8.6% estimation errors" (p.7) against Sreal.
- Tension control, Table 3 (p.9): RMSE Initial 2.3615 N, Adapt1 1.4267 N, Adapt2 1.0449 N, MPC baseline 1.6178 N. "Adapt2 achieves tracking within ±1 N (RMSE: 1.0449 N), outperforming MPC by 35.4%" (p.8). Reduction from Initial: 55.7% (abstract, p.1). Lower is better; RMSE across spans over the run.
- Velocity tracking, Table 3 (p.9): tension RMSE Initial 1.6708 N, Adapt1 0.7902, Adapt2 0.4490, Adapt3 0.2944 N, MPC baseline 1.0102 N. "Adapt2 and Adapt3 maintain tensions within ±1 N ... outperforming MPC by 70.9%" (p.9). Reduction from Initial: 82.4% (p.1).
- LLM diagnosis example: "identified insufficient feedforward compensation during velocity transients and excessive feedback gains" (p.9); anecdotal, single instance.
- Safety filter: Figure 4 caption claims "Simulation-in-the-loop ensures zero unsafe deployments" (p.7), but no count of rejected or unsafe proposals is given.
- Beats non-LLM? Yes on tension RMSE in both scenarios against an MPC baseline (35.4% and 70.9%), but the baseline's tuning is not reported and it was not given the same plant-side adaptation; single simulated runs only.
- Authors' limitation: low unwinding speed was chosen "to focus on validating the LLM-assisted adaptation framework under controlled conditions" (p.8); hardware validation is future work (p.9).

## 7. Terms to define
- Roll-to-roll (R2R): continuous processing of a flexible web unwound from one roll, processed (printed, coated) and rewound.
- Web tension: tensile force in the web in a span between two rollers; the main controlled variable.
- Span: web section between adjacent motorised rollers.
- LQR: linear-quadratic regulator; state feedback u = −Kx from the Riccati equation.
- RAG: retrieval-augmented generation; the LLM retrieves passages from a document base before answering.
- Sim-to-real adaptation: retuning a controller designed on a model so it works on the real plant.
- Safety filter: simulation check of each proposed parameter change for limit, improvement and robustness criteria before deployment.
- Adapt1/2/3: controller parameters after the first, second and third LLM adaptation cycle.
- Constrained autonomy: authors' term for LLM proposes, simulation validates, human oversees.
