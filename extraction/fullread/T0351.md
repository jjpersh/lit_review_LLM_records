## 2. Why it is context
A locally hosted Qwen-7B is connected through the Model Context Protocol (MCP) to a SQL Server database and answers a natural-language request by generating and running a schema query ("Query all columns of CD1") (p.3). No control layer is involved: there is no plant, controller, setpoint or actuator, and the only test is a single before/after demonstration of one database query, with no reported accuracy, latency or stability numbers despite naming those metrics (p.2–4). The queried table holds health-insurance-style fields (FEE_YM, HOSP_ID, TREAT_AMT), not process data (p.3).

## 3. Background use
The paper offers an infrastructure pattern for running a small open-weight model offline in a plant: the model judges intent, an MCP "tool coordination center" calls database or API tools, and results are fed back for the final answer (p.2, Figure 1; p.4). It argues that local deployment keeps proprietary data off the cloud and that JSON-logged tool calls (TOOL_CALL and args blocks) give traceability and auditability (p.4–5). A review could cite it in 5.4 (local and open-weight models) as an example of the data-access plumbing an LLM operator assistant would need, on a single 12 GB GPU server (p.2), but not as evidence of effectiveness. The authors note tool selection relies on predefined rules (p.5).
