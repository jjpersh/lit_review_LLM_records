## 2. Eligibility
Yes, eligible, but only weakly so. A generative LLM (Qwen 2.5 7B run locally via Ollama) is connected to the supervisory layer of a live industrial process. It answers operators' free-form questions over enriched real-time process data and produces diagnostic summaries and maintenance recommendations. It is advisory only and read-only: "cannot issue control commands or modify batch parameters" (p.18). The process is a Clean-in-Place (CIP) system in an operating beverage plant (VivaWild Beverages). This is a process system, not an adjacent domain. The paper has one tested deployment, so it is core, with Advise-level authority.

## 3. What was built, in plain words
The plant is a real CIP skid in a beverage factory, which runs multi-stage cleaning cycles (pre-rinse, alkaline wash, intermediate rinse, sanitizing, final rinse). The existing PLC/SCADA system moves all the actuators (valves, pumps, heating) on a 50–100 ms cycle, and the study left it unchanged (p.14, p.33). The new layer sits on top as a set of software agents ("microservices") that talk over a Redis event bus.
- **Input.** Sensor data (temperature, flow, conductivity, pH, volume) are read passively over MODBUS/serial every 100–1000 ms.
- **Enrichment.** An "Enrichment Agent" applies fuzzy rules and rolling statistics. Each sample is labelled with linguistic values, a NORMAL/WARNING/CRITICAL state, a quality grade between 0 and 1, and short text reasons and actions (pp.19, 29).
- **Deterministic Supervisor.** This rule-based agent raises alarms and can issue emergency stops to the PLC, with no LLM involvement (p.17).
- **The LLM.** The "LLM Assistant" and the "Real-time Monitoring Service" use Qwen 2.5 7B on a local NVIDIA RTX GPU. They receive compact prompts made of aggregate statistics, a few representative records, and metadata about the programme, stage and recent alerts (p.28). They return natural-language answers, charts (via PandasAI-style code generation) and maintenance suggestions to a human operator through a web chat (pp.15, 42).
- **Routing.** An orchestrator classifies each operator intent and sends safety-critical requests to the deterministic path. Structured factual queries are answered by database lookups that bypass the LLM (p.26).
- **What reaches the plant.** Nothing the LLM produces reaches the plant. The output goes only to the operator. The paper describes a "safety barrier" that would validate any LLM-derived command, but the LLM has no command path in this deployment.
- **Model setup.** There is no fine-tuning. The paper calls the approach RAG-style grounding on enriched logs. Prompts and decoding settings are not given.
- **Actuation.** Actuation stays with the PLC: on/off sequencing plus its own regulation. Those loops are not described.

## 4. Each tested setup
**Setup 1: advisory LLM analytics over live CIP data in an operating plant.**
- **Runs.** 24 complete CIP runs were monitored over six months, and 3 were chosen on purpose for analysis (pp.31–32):
  - CIP1: nominal baseline
  - CIP2: preventive warnings (slightly reduced flow, temperature excursions)
  - CIP3: diagnostic alerts (sustained flow and conductivity deviations)
- **Comparator.** None. The paper states the absence of baselines and ablations: no A/B test against traditional SCADA supervision, no comparison of alternative architectures, and no other LLMs or model sizes (p.48). Table 14 compares capabilities qualitatively with "traditional CIP supervision" (p.42), with no numbers.
- **Process and supervisory metrics** (computed per stage for alkaline, sanitizing and final rinse):
  - stage-specification compliance, the fraction of time inside the spec bands
  - state-specification consistency Γs, the fraction of samples where the label agrees with in/out of spec
  - label stability Λs, label changes per minute
  - reaction time from the onset of a critical episode to the alert
  - anticipation window, inspected only qualitatively
- **Metrics defined but not computed.** Alert sensitivity and specificity, plus systematic reaction and anticipation values, are left to future work (pp.34–35, Table 9).
- **LLM metric.** Spot checks compare numbers stated in LLM answers with values recomputed from the logs (median relative error). The number of audited samples is not reported. Three examples are tabulated (Table 13, p.41).
- **What was varied.** Only the operating regime, through which runs were chosen. The model was fixed (Qwen 2.5 7B). Runs and query counts: several dozen operator queries were handled across the three runs (p.42).

## 5. Results
- **LLM numerical fidelity (spot checks).** "the computed values matched those stated in the explanations within small relative tolerances, with median errors below 3% for the audited samples" (pp.40–41).
  - Measures: relative error between numbers stated by the LLM and log-derived values. Lower is better.
  - Denominator: not reported.
  - Table 13 examples:
    - reported "≈73 °C" vs. 72.96 °C computed
    - "≈1.0 L/s" vs. 1.00 L/s
    - "dozens of warnings" vs. 66 warnings and 2 critical samples (p.41)
  - Elsewhere the paper says "median absolute deviations below 2–3%" (p.46).
- **Report fidelity.** "all audited reports in the current case study achieved perfect or near-perfect fidelity for the checked quantities" (p.41). The indicator is the share of numbers within tolerance (for example under 1% relative error). Higher is better. The number of reports is not given.
- **Stage-specification compliance** (Tables 10–11, pp.37–38). Alkaline compliance was CIP1 1.00, CIP2 0.75, CIP3 0.00 (mean 0.58 ± 0.52). Sanitizing was 1.00 for all runs. Higher is better. These figures describe the unchanged PLC-run process, not anything the LLM did.
- **Label consistency** (p.38). "Γs attains a mean value of approximately 0.98" for alkaline stages and 1.00 for sanitizing. Higher is better. This measures the rule-based labelling, not the LLM.
- **Label stability** (p.38). Alkaline stages showed about 0.03 changes/min. The CIP3 final rinse "reaches the order of 10 changes per minute", giving a stage mean of 3.28 ± 5.68 (Table 9, p.37). Lower is better.
- **Reaction time** (p.39). "In CIP 3, the median reaction time is approximately 35–36 s", from the onset of a critical episode to the alert from the deterministic supervisor. Lower is better. Only one run had critical episodes.
- **LLM latency.**
  - Table 7 (p.30): "LLM query (median) … 1–2 s", against "<100 ms" for the deterministic state update.
  - p.40: "End-to-end LLM response times for diagnostic queries remained in the order of a few seconds across all executions".
- **Usage.** "the conversational interface handled several dozen real-time queries" across the three runs (p.42).
- **LLM vs. non-LLM.** The paper does not show the LLM beating any non-LLM alternative on any metric. The authors say explicitly that it "does not quantitatively compare its effectiveness against" traditional supervision (p.48).

## 7. Terms to define
- **CIP (Clean-in-Place):** automated multi-stage cleaning of process equipment without taking it apart (rinse, alkaline wash, sanitize, final rinse).
- **Deterministic Supervisor:** rule-based agent that computes NORMAL/WARNING/CRITICAL states and can issue emergency stops to the PLC. It contains no LLM.
- **Temporal domain separation:** the authors' term for routing hard-real-time (<100 ms) supervision and soft-real-time (1–2 s) LLM analytics through separate paths.
- **Signal Enrichment Pipeline:** fuzzy-logic and rolling-statistics layer that turns raw sensor values into linguistic labels, trend indicators and quality grades for the LLM to read.
- **Stage-specification compliance:** fraction of sampled time in a stage during which all monitored variables are inside their prescribed bands.
- **State-specification consistency (Γs):** fraction of samples where the supervisory label agrees with in-spec/out-of-spec status.
- **Stability of state labeling (Λs):** number of label changes per minute in a stage.
- **RAG (retrieval-augmented generation):** adding retrieved process data or summaries to the LLM prompt so answers rest on logged values.
- **Ollama:** local runtime for serving open-weight LLMs on premises.
