## 2. Eligibility
Yes, in one setup. In Case Study 3 (pp.12–15), LLMs propose the full NMPC formulation (objective, horizons, weights and constraints) for a simulated batch crystallizer. The authors implement each proposal as written and run it in closed loop. The LLM therefore designs and tunes a control layer offline. Case Studies 1 (ATR–FTIR soft-sensor calibration) and 2 (population-balance modelling and model updating) are PSE modelling tasks that feed monitoring and control, but they do not themselves touch a control loop. The domain is a process system (batch cooling crystallization of potassium sulfate), so it is not adjacent. Recommend `core`, on the strength of Case Study 3. CS1 and CS2 are graded as separate setups for completeness.

## 3. What was built, in plain words
Four LLM systems were each given the same opening prompt and then follow-up prompts that differed by system "to guarantee the best performance of each approach" (p.4):
- Dyad 2.1 (multi-agent): JuliaHub's modelling platform built on a Claude Opus backbone. It writes models in an acausal modelling language and compiles them to Julia ModelingToolkit/SciML. Before simulating, it checks for an equal number of equations and unknowns, the DAE index, and conservation laws, and it debugs from failure symptoms back to their causes (pp.3–4).
- Claude Opus 4.6: treated as a general-purpose multi-agent system.
- ChatGPT 5.2 and Gemini Pro 3: single-agent baselines.

All agents ran locally on an i7 laptop-class workstation and could write and execute Python and Julia code (p.4, p.7).

In Case Study 3, the plant is a simulation only. It is the PBM (population balance model: moment ODEs for nucleation, growth and dissolution) that Dyad fitted to lab data. The controller that moves the actuator is a conventional NMPC: CasADi, IPOPT, single shooting, IDAS integrator, 1-min sampling. It manipulates crystallizer temperature, which is a continuous actuator, to control mean crystal size L10 = μ1/μ0 and crystal mass m (pp.13–14).

The LLM sits entirely offline, at the design stage. It receives the earlier modelling context and the question "Can you tell me the control formulation (say the objective function with the tuning parameters and the constraints)?" (p.13). It returns horizons P and M, tracking weights δ, terminal weights θ, a move penalty λ, temperature bounds and rate bounds (Table 7, p.14). Each NMPC uses that LLM's own PBM as its internal model. The authors code the NMPC with an existing Python package. No validator, gate or safety check is applied to the LLM's tuning beyond the authors running it. The LLM never acts at run time.

## 4. Each tested setup
**Setup A: Case Study 1, ATR–FTIR calibration (soft sensor).**
- Data: 247 lab spectra from paracetamol/ethanol/water batches in a Mettler-Toledo Optimax, split randomly 55/15/30 (p.4).
- All four LLMs built calibration models. Each was run once; no repeats were reported.
- Metrics: RMSE, MAE and R² on the train, validation and test sets (Fig. 2).
- No non-LLM or human-built baseline was used.

**Setup B: Case Study 2, PBM development and updating.**
- Dissolution: 4 calibration batches and 1 validation batch (p.7).
- Crystallization: 7 seeded batches (p.7). The text does not give the calibration/validation split clearly. The prompt says the file holds "four batch experiments", while the text says seven.
- Comparator: the PBM published by Moraes et al., built by human experts without an LLM (Figs. 4–7).
- Metrics: MSLE and R² per moment and concentration.
- Off-nominal tests:
  - Long-horizon extrapolation to equilibrium (Fig. 8).
  - Model updating under dataset shift: ten simulated batches with kg×2.6 and kb×3.2, plus multiplicative noise of 8% on the moments and 1% on C (pp.10–12). Only Dyad and Claude were tested here.
- Each LLM was run once.

**Setup C: Case Study 3, LLM-proposed NMPC formulation and tuning.**
- NMPCs from Dyad, Claude Opus and Gemini were tested. ChatGPT was excluded because its PBM was poor (p.13).
- Five simulated batches with different initial states and set-points (Table 6, p.14).
- The plant model is Dyad's PBM. The Claude and Gemini NMPCs therefore run with plant-model mismatch, while the Dyad NMPC's internal model matches the plant.
- Metrics:
  - End-of-batch L10 and m against set-point
  - Control effort Σ Δu² (Table 8)
  - Mean and maximum NMPC solve time (Table 9)
- No non-LLM NMPC tuning was used as a baseline, whether by a human expert, a prior paper or a systematic method.
- One run per LLM per case.
- No disturbances, noise or faults.

## 5. Results
- **CS1 (p.6):** "All LLM-generated models deliver high predictive fidelity, with R2 remaining close to unity across all datasets". Gemini's 15-component PLSR was best. Dyad's 10-component PCR had higher error. The numbers appear only in Fig. 2.
- **CS2 dissolution (p.7):** ChatGPT showed "strongly degraded (and in some cases negative) R2 for the moments" on validation. Dyad and Claude kept high R² and low MSLE (lower is better).
- **CS2 crystallization (p.10):** Multi-agent solutions "exhibit consistently low MSLE and high R2 for all five targets". Gemini had "strongly negative R2 for at least one moment". Claude matched the human-built Moraes PBM. Dyad's model showed a time shift.
- **CS2 long horizon (p.10):** Claude's model and the Moraes model show "persistent drift in the moments". Only Dyad's model settles at equilibrium.
- **CS2 interaction time (p.10):** Claude Opus "required at least two hours per prompt", versus "approximately 15–20 min per prompt" for the others.
- **CS2 model update (p.12):** Both models "improved substantially". Claude's post-update RMSLE was lower than Dyad's (Fig. 10).
- **CS3, Table 8 (p.15).** Control effort Σ Δu² is in K²; lower is better.

  | Case | Set-point | Dyad | Claude | Gemini |
  |---|---|---|---|---|
  | 1 | L10 16.00 / m 20.00 | L10 17.14 / m 22.35 / effort 8.76 | L10 16.79 / m 24.43 / effort 22.25 | L10 16.64 / m 24.78 / effort 18.86 |
  | 2 | m 25.00 | m 25.21 / effort 10.50 | m 28.98 / effort 22.73 | m 27.05 / effort 19.74 |
  | 5 | m 12.00 | m 14.22 | m 14.33 | m 24.21 / effort 18.56 |

  The paper's wording: "all three NMPCs exhibited steady offsets in at least one output", because one manipulated variable serves two controlled variables. "In Cases 4–5, all controllers significantly overshot L10." For example, in Case 4 L10 was 17.27, 18.24 and 16.93 against a set-point of 14.
- **CS3, Table 9 (p.15):** Mean / max NMPC solve times were Dyad 0.785 / 19.690 s, Claude 0.942 / 11.172 s, and Gemini 0.248 / 3.560 s. All are below the 1-min sample time. These are NMPC solver times, not LLM latency.
- **Authors' conclusion (p.15):** "Dyad delivered the best overall performance, achieving the most reliable compromise between L10 and m with comparatively low control effort".

**LLM versus non-LLM:** The paper does not show any LLM beating a non-LLM alternative on control. It has no non-LLM NMPC baseline, and the comparisons are between LLMs only. In modelling (CS2), Claude's model matched the human-built literature PBM within the data window but drifted at long horizon, and Dyad's model was more physically consistent at equilibrium than the literature PBM (p.10).

**Stated limitations:**
- The Moraes batches did not reach equilibrium, so the fitted nucleation term does not shut off at saturation, which is an overfitting risk (p.10).
- Claude's slow interaction time (p.10).
- One manipulated variable cannot track two outputs at once (p.14).

## 6. Duplicates
The experimental data are reused from earlier work by the same group:
- crystallization and dissolution batches from Moraes et al. [51,55];
- the ATR–FTIR spectra from Lima [43].

The NMPC objective follows the group's earlier crystallization NMPC [44,51]. The LLM experiments themselves appear to be new. No duplicate LLM study was identified from the text.

## 7. Terms to define
- PSE: process systems engineering.
- ATR–FTIR: attenuated total reflection Fourier-transform infrared spectroscopy, used here as an in-line concentration sensor.
- PLSR / PCR: partial least squares regression / principal component regression, both latent-variable linear calibration methods.
- SNV: standard normal variate, a spectral preprocessing step.
- PBM: population balance model, here reduced to ODEs for the crystal size distribution moments μ0–μ3.
- μi: the i-th moment of the crystal size distribution. μ0 is number density and μ3 is proportional to crystal volume.
- L10: mean crystal size, μ1/μ0.
- MSLE / RMSLE: (root) mean squared logarithmic error; lower is better.
- NMPC: nonlinear model predictive control.
- P, M: prediction and control horizons.
- δ, θ, λ: stage tracking weight, terminal tracking weight and move-suppression weight.
- Dyad: JuliaHub's AI-enabled acausal modelling platform with a Claude backbone and compile/simulate/validate loops.
- Multi-agent vs single-agent: in this paper, an orchestrated, tool-using workflow of several agents versus one chat model working in a single pass.
- Dataset shift / model update: re-fitting the PBM parameters after the process kinetics change.
