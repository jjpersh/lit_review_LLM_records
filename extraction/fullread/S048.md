## 2. Eligibility
Yes. A local generative LLM (Llama 3 served by Ollama) is the feedback controller. At every sampling step it reads the temperature and the previous action and writes the binary heater command, so it acts directly on the actuator. The plant is a simulated first-order industrial oven thermal model, which is a process system. The paper tests its own setup in simulation, so it is core.

## 3. What was built, in plain words
The plant is a simulated oven, not hardware. It is a discrete first-order lumped thermal model, T(k+1) = 0.99·T(k) + 10·u(k), with a sampling time Ts = 1 s and τ ≈ 100 Ts (p.5–6). The heater is on/off (u ∈ {0,1}), so actuation is binary, not continuous. The control objective is to keep the temperature inside a deadband of 140–160 °C around a 150 °C setpoint.

No conventional controller sits between the LLM and the actuator. The LLM *is* the controller: a relay with hysteresis, written in plain English. The system prompt (Listing 1, p.7) states the rules:
- u = 1 below 140 °C
- u = 0 at or above 160 °C
- otherwise keep the previous u

At each step a "Context" block and a "Prompt Generator" build a query from the last temperature reading T(k−1) and the previous action u(k−1) (Listing 2, p.7). The model must answer with one token. Decoding is deterministic: greedy, temperature 0, num_predict = 1.

An "Answer Evaluator" (the validator) checks the reply against the regular expression ^[01]$. If the reply is invalid, the same prompt is retried up to N_max times. If all retries fail, a hard-coded relay (Eq. 5) supplies that step's command (p.7–8, Fig. 1). No optimizer, simulation check or human approval sits in the loop.

The model is "llama3:{size}" run locally on a desktop CPU. The paper never states the size. There is no fine-tuning and no tool use. The comparator is the same relay law in code, run on the same one-step-delayed timing.

## 4. Each tested setup
There is one architecture: the LLM writes the on/off heater command directly, guarded by a schema validator, retries and a coded fallback. It was run under these conditions:
- **Nominal run.** A "representative" single run from T(0) = 0 °C, u(−1) = 1. The stated horizon is K = 1000 steps for the stability check and K = 200 steps for the sensitivity and ablation studies (p.8). It is unclear which horizon Table 2 uses; Figure 2 shows 200 steps. Comparator: the coded relay with hysteresis, implementing the identical rule. It is a correct non-LLM implementation of the same policy, not PID or MPC. Metrics: agreement %, switch count, band time %, LLM failure count. Dwell ratio, overshoot, entry time and latency are defined but never reported numerically (p.8–9).
- **Measurement noise.** Gaussian noise with σ = 2.0 °C is added to the measured temperature; the plant itself is unchanged. One run, compared with the clean run (Table 3, p.12).
- **Parameter sweeps.** α ∈ {0.985, 0.99, 0.995} and β ∈ {8, 10, 12} were announced (p.8). The text says Switches and Band time adjust "as shown in Table 3" (p.12), but no sweep results are reported.
- **Ablation (no hold).** The prompt is replaced with a simple threshold at 150 °C, with no memory (p.12). Reported: switches and band time compared with the hysteresis prompt (Table 4, p.13).

Varied across conditions: the noise level, the policy prompt (with or without memory), and (nominally) the plant parameters. Only one LLM was used. No repeated runs or seeds are reported; rng(1) is mentioned only as an option for fixing noise (p.5).

## 5. Results
- Nominal agreement (p.10, Table 2): "Agreement (%) … 100.00"; "LLM failures (count) … 0". Agreement is the share of steps where the LLM action equals the coded-relay action (denominator K steps; higher is better). Failures count the steps that needed the fallback.
- Switching (p.10): "The Switch counts (20) are identical". Switches count ON/OFF transitions, a chatter proxy; lower is better. Band time was 70.15% for both, i.e. the share of steps with T in [140, 160] °C (higher is better).
- Noise (p.12, Table 3): "Switches (count) 20 21"; "Band Time (%) 70.15 74.13"; "Agreement (%) 100 73.13". Under σ = 2.0, the LLM and the relay disagreed on about 27% of steps. The authors do not discuss this beyond saying that agreement "may drop" when noisy readings sit near a boundary (p.12). This sits oddly with their claim that both controllers see identical information.
- Ablation (p.13): "removing the memory logic improves Band time slightly (92% vs. 70%) but causes a nearly 3× increase in Switches (58 vs. 20)". This compares two LLM prompts. It shows the value of hysteresis, not of the LLM.
- Safeguard: "the LLM consistently produced valid tokens, resulting in zero failures" (p.14). The fallback was never exercised.
- Internal inconsistencies:
  - p.10 says "The few mismatches are aligned with the steps where the validator rejected the LLM output", which contradicts 100% agreement and 0 failures.
  - p.11 describes Figure 4 as an error plot err(k), but the Figure 4 caption describes the noise experiment.
  - p.13 says "matched the relay on most steps Agreement = 100%".
- **Does the LLM beat a non-LLM alternative?** No. At best it equals the coded relay in nominal conditions (identical switches and band time), and it agrees less under noise. The paper claims equivalence, not superiority. It reports no inference latency, even though latency was logged (p.8).
- Authors' limitations: "This is a single-plant, single-horizon study on a SISO process with binary actuation" (p.16). "Due to variable inference latency, this approach is currently limited to systems with slow dynamics" (p.15). They also acknowledge that a multi-seed Monte Carlo analysis is lacking (p.15).

## 6. Duplicates
None identified from the paper. No other paper by the same authors on this plant is cited as reporting the same experiment. Data and code are "available on request" (p.17).

## 7. Terms to define
- Relay with hysteresis (deadband): an on/off controller that switches ON at the lower threshold and OFF at the upper one, and holds its last action in between.
- Hold-last-action (memory branch): the rule u(k) = u(k−1) inside the deadband, which prevents chatter.
- Agreement (%): the percentage of steps where the LLM's binary action equals the coded relay's action.
- Band time (%): the percentage of steps with temperature inside [140, 160] °C.
- Switches: the number of ON/OFF transitions of the heater command.
- Dwell ratio: the fraction of in-band steps where the action did not change (defined; not reported).
- Schema → retries → fallback: the output must match ^[01]$; invalid replies are re-queried, and if that fails the coded relay sets the action.
- Greedy decoding / num_predict = 1: temperature-0 deterministic generation limited to a single output token.
- Ollama: local LLM serving software.
- ZOH discretization: zero-order-hold conversion of the continuous first-order thermal model to discrete time.
