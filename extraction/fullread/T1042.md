## 2. Eligibility
Yes. A generative LLM agent (OpenAI gpt-4.1-mini as "Optimizer Agent", supervised by an o3-mini "PID Control Agent") reads live performance metrics and writes new PID gains to a running hardware control loop. The plant is a Quanser QUBE-Servo 2 DC servo motor with an inertia disk, which is an adjacent domain (motor drive or servo), not a process system. The setup was tested on real hardware, so the paper is core.

## 3. What was built, in plain words
The plant is a physical Quanser QUBE-Servo 2, a small coreless DC motor with a 2048-count optical encoder and a load disk. A Python program runs a discrete PID position loop at 500 Hz. It tracks a square-wave reference of ±π/3 rad with a 12 s period, filters the derivative term with a first-order filter (Td = 0.005 s), and clips the motor voltage to ±8 V (pp.4-5, 7). This PID moves the actuator continuously. The LLM never writes the voltage.

The LLM sits above the PID as a gain tuner. A Flask web server exposes REST endpoints: GetMetrics returns the overshoot, steady-state error, rise and settling time, and IAE/ISE/MAE/RMSE/ITAE/ITSE computed after each positive square-wave step. GetPID returns the current gains. UpdatePID writes new gains into the running loop (pp.7-9). The n8n platform orchestrates two agents. n8n is an open-source, low-code workflow automation tool. The "PID Control Agent" (o3-mini) is a chat-triggered supervisor. It checks the metrics and calls the "Optimizer Agent" (gpt-4.1-mini) as a sub-workflow (pp.7-8). The Optimizer Agent repeatedly reads metrics and gains, reasons, and posts new Kp/Ki/Kd values. At the end it returns a natural-language explanation and the final gains.

There are two Optimizer prompts. The guided prompt (Appendix A.2) gives a step-by-step heuristic with fixed increments and thresholds. The unguided prompt (Appendix A.3) gives only the role, the safe ranges (Kp 0.1-2.5, Ki 0-1.0, Kd 0-0.25) and the instruction "use your knowledge". The safe ranges are enforced only by the prompt: the agent is told to abort if the gains go out of range. The paper describes no code-level validator or human approval. The only hard limit is the ±8 V voltage clip. There is no fine-tuning, and the tools are the three REST nodes.

## 4. Each tested setup
1. **Guided-prompt live tuning (gpt-4.1-mini, Appendix A.2).** Hardware runs start from Kp=0.1, Ki=0, Kd=0. Table 1 reports final gains for 3 runs (p.12). Error-metric time traces are shown for Run 3 only (Figs. 8-10, pp.12-13). Roughly 10 runs are implied in total ("about 1 out of 10 runs", p.15). There is no non-LLM comparator: the only reference is the arbitrary initial gains. The metrics are IAE, ISE, MAE, RMSE, ITAE and ITSE over time, plus overshoot, SSE and rise time cited in the agent text. There were no disturbance or fault tests.
2. **Unguided-prompt live tuning (gpt-4.1-mini, Appendix A.3).** The architecture and plant are the same, but the LLM chooses its own step sizes within the safe range. Table 1 reports 3 runs, and the traces again show Run 3. A failure rate of about 1 in 10 runs is reported (p.15). There is no non-LLM comparator.
3. **Human-machine dialogue (o3-mini PID Control Agent chat).** The agent answered three questions: why it reduced Kp, what to do if load torque rises 10%, and whether to double the sampling rate (Figs. 11-13, Appendix C.1). This is advisory text only. The load-torque change was not applied to the plant, and the answers were not evaluated quantitatively.

The two prompt variants share one architecture and safeguard. I grade them as separate rows because the paper's main comparison is between them, but the authority and C6 grades are identical.

## 5. Results
- Both strategies reduced the error integrals during tuning: "both tuning methods, whether guided by system prompts or not, were effective in reducing the Integral Absolute Error (IAE) and Integral Squared Error (ISE)" (p.12). The figure values are not available as text. This comes from one run (Run 3) per strategy, and lower is better.
- Time-weighted metrics were not reduced: "they were less effective in reducing ITAE and ITSE" (p.16). The authors attribute this to small oscillations and noise near the setpoint (p.15).
- Final gains for the guided prompt, Run 2: "Kp = 0.125, Ki = 0.10, and Kd = 0.025", reached "around 104 s" (p.10). Run 3's agent self-report: "steady-state error around 0.21 ... low rise time of about 0.18 s" (pp.10-11). These are LLM-reported values, not independent measurements.
- Unguided-prompt convergence was faster: "it typically found optimal parameters relatively fast (e.g., 50 to 80 s)" (p.11). Table 1 shows Kp spread 0.35-0.80 across 3 runs versus 0.125-0.3375 guided (p.12).
- Failure rate: "about 1 out of 10 runs ... the AI operating without a system prompt instruction failed to produce a final PID value" (p.15). The denominator is about 10 runs, so this is approximate. No failures are reported for the guided prompt.
- Safety claim: "the AI agent always stayed within safe limits" (p.10). This is a qualitative claim with no count.
- The paper does **not** show the LLM beating any non-LLM alternative. There is no comparison with Ziegler-Nichols, relay or Quanser-recommended tuning. The only improvement shown is against the deliberately poor starting gains (Kp=0.1, Ki=Kd=0).
- Model spread: only gpt-4.1-mini was used as the tuner. o3-mini supervised and chatted, and no other models were compared.

## 7. Terms to define
- QUBE-Servo 2: Quanser's compact DC servo teaching rig with an encoder and an inertia-disk or pendulum attachment.
- n8n: an open-source, low-code workflow automation platform used to chain LLM agents and REST calls.
- Flask server: a Python web server exposing the GetMetrics, GetPID and UpdatePID endpoints to the agents.
- PID Control Agent: the supervisor agent (o3-mini) that checks metrics and calls the optimizer, and also chats with the user.
- Optimizer Agent: the gpt-4.1-mini sub-workflow that iteratively writes new PID gains.
- Guided versus unguided system prompt: a stepwise tuning heuristic in the prompt (A.2) versus "use your knowledge" within safe ranges (A.3).
- Safe range: the prompt-stated gain bounds (Kp 0.1-2.5, Ki 0-1.0, Kd 0-0.25) that the agent is told not to exceed.
- ITAE and ITSE: integrals of time-weighted absolute and squared error, which penalise late, persistent error.
- Adaptive derivative filter: first-order smoothing of the derivative with α = Td/(Td+Δt), where Td = 0.005 s.
