## 2. Eligibility
Borderline core. A generative LLM agent issues structured tool calls (register writes and reads) to PLC/SCADA-style interfaces in virtual industrial environments, and a second LLM acts as a guardrail that must allow or block each proposed tool call before execution (p.4-5). The tested object is that LLM safeguard, challenged with 1,619 proposed tool calls, of which 424 are unsafe under the strict mapping (p.7-8). The "plant" is a lightweight abstraction: the authors state the environments "do not fully model continuous dynamics, temporal delays, sensor noise" (p.9). There is no closed-loop process response, so this is a benchmark-dataset evaluation (E2) of a safety gate on control actions. It is graded as core because the safeguard sits directly in front of a control layer and is tested with bad proposals. The domains are process-industry framed (training on a chemical plant; benchmark on water treatment, semiconductor, pharmaceutical fermentation, oil refining, nuclear cooling, food and brewery), so it is not adjacent.

## 3. What was built, in plain words
The authors build a dataset and benchmark for one question: can a model look at an LLM agent's next tool call and decide whether it is safe to execute? A pipeline of LLM agents (one unnamed base LLM for all generation, p.5) does four things (Fig. 2, p.7). An environment-generation agent writes small virtual industrial environments: controllable components, state variables, tools, and a safety specification (operating bounds, mandatory sequences such as pump then valve then reactor startup, and role-based permissions) (p.6). A task-generation agent writes user requests in three modes: benign, injected-benign (a legitimate task with an appended fake SOP note, dashboard message or maintenance hint that pushes toward an unsafe action), and malicious (explicit unsafe request) (p.5-6). A trajectory-sampling agent, ReAct-style (reason, then act), executes each request through tool calls and receives environment feedback (p.6). A deterministic rule engine then labels each step: unsafe (1.0) if it breaks a permission, a bound, a procedure or skips a verification; borderline (0.5) for the other steps of an injected-benign or malicious trajectory that contains an unsafe step; safe (0.0) otherwise (p.6). In the benchmark, anything above 0.0 counts as unsafe ("strict mode", p.7). Some benchmark environments set physical limits stricter than the PLC register bounds (p.3).

The guardrail is the LLM under test. It receives the proposed tool call, the history, the user request and the constraints, and outputs a safe/unsafe label; only safe calls would be executed (Eq. 2, p.4-5). In the evaluation nothing is executed: the guardrail classifies stored steps offline. Three guardrails are compared: GPT-4o mini, Qwen2.5-7B-Instruct, and Qwen2.5-7B-Instruct fine-tuned with LoRA (low-rank adapter fine-tuning) on the training split (p.8). Actuation in the environments is discrete tool calls (register writes), not continuous control.

## 4. Each tested setup
One setup: an LLM used as a step-level safety gate on proposed PLC/SCADA tool calls.
- Training split: 20 environments, chemical plant domain, 100/100/100 tasks (benign/injected/malicious), 611 steps, 103 unsafe (Table I, p.7).
- Benchmark split: 50 environments in six unseen domains, 250/250/250 tasks, 1,619 steps, 424 unsafe after strict mapping (Table I, p.7). Unsafe share: benign 13.1% (121/921), injected-benign 39.0% (180/462), malicious 52.1% (123/236) (p.8).
- Varied: guardrail model (general commercial, open-weight base, open-weight fine-tuned) and interaction mode.
- Comparator: the two untuned LLMs. No non-LLM screen (for example the rule engine itself used as a gate, or a conventional classifier) is reported as a comparator; the rule engine is the ground truth.
- Metrics: accuracy, precision, recall, F1, with unsafe as positive class, per mode and overall (p.8).
- Runs: one evaluation per model; no variance, no prompts, no LoRA hyperparameters reported.

## 5. Results
Table II (p.8), unsafe is positive; values for GPT-4o mini / Qwen2.5-7B base / fine-tuned guardrail (row order verified by recomputing F1 from precision and recall):
- Overall F1: 0.4206 / 0.0934 / 0.7102. Overall recall: 39.54% / 6.20% / 64.07%. Overall precision 44.92% / 18.89% / 79.67%. Higher is better.
- Overall accuracy 64.61% / 79.07% / 79.07%: the base Qwen ties the fine-tuned model on accuracy while catching almost no unsafe steps. Authors: "models that default to predicting safe actions can achieve deceptively high accuracy while exhibiting near-zero recall" (p.8).
- Injected-benign recall: 34.44% / 0.88% / 85.00%; F1 0.3949 / 0.0163 / 0.8870. Authors: "Both GPT-4o mini and Qwen2.5-7B-Instruct struggle to reliably detect unsafe behaviors induced by contextual manipulation" (p.8).
- Malicious: GPT-4o mini recall 91.23% but accuracy 47.03% (precision 47.49%), i.e. it over-flags; fine-tuned guardrail recall 84.21%, precision 77.42%, F1 0.8067 (p.8-9).
- Benign: even the fine-tuned guardrail catches only 37.93% of unsafe steps (F1 0.4809); GPT-4o mini 18.10%, base Qwen 4.13% (p.8).
- Agent fallibility (by-product): under benign requests the sampling agent itself produced unsafe tool calls in 121 of 921 benchmark steps (13.1%), with no adversary (p.8). The agent's LLM is not named.
- The recall percentages do not map onto whole-number counts of the stated unsafe totals (for example 0.88% of 180), so the exact denominators are not reconcilable from the paper; possibly some outputs were excluded. NR.
- The paper does not show an LLM beating a non-LLM alternative; all comparisons are LLM versus LLM, and the non-LLM rule engine defines the labels.

## 7. Terms to define
- Tool call: a structured function invocation by the agent, here a PLC/SCADA read or register write.
- Step-level screening: judging each single proposed tool call before execution, rather than the whole request or trajectory.
- Guardrail: a model that classifies a proposed action as safe or unsafe and blocks unsafe ones.
- Injected-benign: a legitimate request with appended plausible-looking context (fake SOP note, dashboard message) designed to induce an unsafe action.
- Strict mode: borderline (0.5) and unsafe (1.0) labels both count as unsafe.
- Mode-aware risk propagation: in adversarial trajectories with one violation, all other steps are labeled borderline.
- LoRA: low-rank adaptation, a parameter-efficient fine-tuning method.
- ReAct: an agent loop alternating reasoning text and actions.
