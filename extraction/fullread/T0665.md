## 2. Eligibility
Yes, but only at the advisory level. A generative LLM (GPT-4o, accessed through the API) is linked to a greenhouse Model Predictive Control (MPC) layer. It explains the MPC's planned control decisions (heating, cooling, ventilation, CO2 injection and reference trajectories) to growers through a chatbot. It never acts on the controller, tunes it or sets its targets. The plant is a tomato greenhouse, which counts as an adjacent domain (greenhouse). There is a tested setup: 100 evaluated responses compared with a non-LLM keyword/template baseline. The paper is therefore core, at the explanation/advice end of the scope. It contains no closed-loop experiment.

## 3. What was built, in plain words
There is no hardware and no live plant. The authors took an existing simulated dataset from a hierarchical greenhouse MPC by Sathyanarayanan et al. [4]. That MPC was solved offline with real 2011 weather data from a Berlin greenhouse facility. The data are planned reference trajectories at 5-minute intervals, March to October 2011 (p.3), covering indoor temperature, humidity, CO2, biomass, heating, cooling, ventilation, CO2 injection, outdoor temperature, outdoor humidity and solar radiation. In that original work the MPC was the controller that moved the actuators (continuous heating, cooling, vent and CO2 flows). In this paper nothing is actuated.

The LLM sits beside the controller as an explanation layer, which the authors call ARAG (Adaptive Retrieval-Augmented Generation). The pipeline runs in this order:
1. Preprocessing: K-means/EVT clustering from earlier work, a sliding-window gradual-change detector (5 steps, threshold 0.0001) and Pearson correlations with |r| > 0.7 turn the trajectories into a structured "document plan" (p.3).
2. Chunking and embedding: the text is split into 200-token chunks with 50-token overlap and embedded with all-MiniLM-L6-v2 (p.5, p.8).
3. Retrieval and generation: for each grower query, the top-3 chunks by cosine similarity are passed to GPT-4o (temperature 0.3), which writes a natural-language explanation. Role-based prompt templates adapt the explanation to an operator or a supervisor (pp.5-6, p.8, p.9).
4. Feedback: grower feedback (yes/no/partial) raises or lowers chunk weights (×1.15 / ×0.85, or +0.15 / −0.1) for later retrieval (p.5, p.6).

The output goes only to a human. It never reaches the plant, so there is no validator, gate or safety check on control actions. The Streamlit chatbot is the interface.

## 4. Each tested setup
**Setup 1: ARAG chatbot that explains offline greenhouse MPC trajectories to growers (advisory only).**
- Conditions: queries about the pre-loaded simulated MPC dataset. No closed loop, and no disturbance or fault scenarios are designed in as tests.
- Runs: 100 sample responses "collected from users engaged with the system" (p.9). 100 expert evaluations by "research domain specialists" (p.8). There are no repeated runs of the same query.
- Comparator: a non-LLM baseline with keyword-based chunking, exact keyword retrieval and fixed template responses (p.6, p.7). The paper says it was built "to highlight the limitations of traditional approaches" (p.6), so it is a deliberately simple strawman, not a tuned retrieval system. The paper also compares two prompt variants with GPT-4o (base vs refined prompting, Table 5, p.10) and two models (GPT-4 vs GPT-4o, Table 2, p.4) within the same architecture.
- Metrics: ROUGE-L, BERTScore, a "Relevance" score, Wilcoxon signed-rank test with Hodges-Lehmann 95% confidence intervals, and response time. There are no control metrics.
- What was varied: retrieval/generation method (baseline vs ARAG), prompting (base vs refined) and model (GPT-4 vs GPT-4o).

## 5. Results
- ARAG vs baseline (Table 3, p.9), n = 100 responses, higher is better: ROUGE-L 0.05 → 0.07, BERTScore 0.68 → 0.79, Relevance 0.41 → 0.57. Quote: "BERTScore ... improved by 12.1%" (p.9). Quote: "the Relevance score ... showed an improvement of 38.3%" (p.9). Relevance is a paper-specific score of how directly a response answers the query, higher is better. The paper does not define its scale or how it was scored.
- Statistics (Table 4, p.9-10): "ROUGE-L (Z = -5.97, p < 0.001, r = 0.42)". Relevance had Z = −6.81 and r = 0.48. Hodges-Lehmann 95% CI for Relevance: [0.130, 0.182].
- Prompting (Table 5, p.10): "The ROUGE-L score improved by 14.3%, BERTScore improved by 4.59%, and Relevance improved by 11.33%" for refined over base prompting.
- Model choice (Table 2, p.4): GPT-4o vs GPT-4 response time 2.17 s vs 3.82 s, ROUGE-L 0.84 vs 0.73, BERTScore 0.92 vs 0.87. Quote: "Response time decreased by 43.2%" (p.4). The denominator and test set for this table are NR.
- Latency trade-off (Fig. 8, p.10), single query "What is the temperature trend today?": "Response Time: 21.1 sec (Baseline: 8.4 sec)". ARAG is slower than the baseline.
- Qualitative case studies (Figs. 12-14, pp.13-15) show the chatbot reading correlations from the data (for example indoor vs outdoor temperature r = 0.95). In one case it correctly notes that a humidity drop came before the vent opening (p.13). These are anecdotes and are not scored.
- LLM vs non-LLM: the LLM system beats a non-LLM keyword/template baseline, but only on text-similarity and relevance metrics. There is no control-performance comparison, and the LLM has no effect on control performance.

## 7. Terms to define
- MPC (Model Predictive Control): optimizer that plans control moves over a horizon (here 24 h) using a plant model and weather forecasts.
- RAG (Retrieval-Augmented Generation): retrieving stored text chunks relevant to a query and passing them to the LLM as context.
- ARAG (Adaptive RAG): the authors' RAG variant, with context-aware ranking, feedback-driven chunk reweighting and role-based prompts.
- Chunk: a 200-token text segment of the processed MPC trajectories with 50-token overlap, used as the retrieval unit.
- all-MiniLM-L6-v2: a small SentenceTransformer embedding model that converts text into vectors for cosine-similarity search.
- ROUGE-L: lexical overlap (longest common subsequence) with an expert reference explanation, higher is better.
- BERTScore: embedding-based semantic similarity to a reference text, higher is better.
- Relevance score: the paper's score of how directly a response addresses the query, higher is better. Its scale is not specified.
- Soft/hard constraint: the MPC's preferred band (for example 18-26 °C) vs its absolute limit (for example 14 °C), as cited in the explanations.
- Venlo-type greenhouse: a standard glass greenhouse design common in commercial horticulture.
- EVT (Extreme Value Theorem): used with K-means in the earlier work to detect trend changes.
